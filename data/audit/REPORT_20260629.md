## Findings & actions

### 🔴 #1 Wrong photos — cross-species contamination (BIGGEST issue)
**Root cause:** a since-reverted `best_match results[0]` wrong-tid bug pulled iNat
photos under WRONG taxon_ids. The earlier revert NULLed `species.inat_taxon_id`
and most `photo_url`, but **left the `species_photo` gallery rows and some heroes
behind**. Symptom: one photograph attached to up to **36 unrelated species**
(a peony + a camellia + ferns all showing the same image).

Fixes (all reversible via `species_photo_quarantine`):
- **FIX #1** (`/tmp/fix_orphan_photos.py`): 60 species with `inat_taxon_id IS NULL`
  yet iNat gallery rows → quarantined **302** gallery rows; repointed **59**
  heroes (8→Commons/GBIF, 51→NULL).
- **FIX #2** (`/tmp/fix_orphan_hero.py`): 60 more tid-NULL species whose bare
  `photo_url` was a shared iNat URL → repointed **60** (12→Commons/GBIF, 48→NULL).
- **FIX #4a/4b** (`/tmp/fix4a_shared_gallery.py` + collect_species_photos refill):
  quarantined **all 232** remaining cross-species-shared `species_photo` rows +
  **14** shared heroes, then **refilled galleries strictly from each species'
  OWN inat_taxon_id** (an iNat observation photo belongs to exactly one taxon, so
  refilled photos can no longer be shared). +1 genus/subgenus-stub leftover row.

**Result: shared `species_photo` URL groups 169 → 0; shared hero photo_url 21 → 0.**
No photo is shown for a species it doesn't depict anymore.

### 🟠 #2 Duplicate species — same iNat taxon_id (13 pairs)
13 pairs of species rows shared one `inat_taxon_id` (synonyms / Latin
gender-variants: e.g. *Venerupis aspera* = *Ruditapes aspera*; *Ixobrychus* =
*Botaurus eurhythmus*; *…oxycephala/oxycephalus*).
- **FIX #3** (`/tmp/merge_dups.py`): merged each into the curated/profiled
  (iNat-accepted-name) row via `scripts.merge_species_pair`; source binomial kept
  as a `sci` alias; full source row snapshotted to `species_merged_log` BEFORE
  deletion. One documented exception (tid 243930) keeps the richer 36-park
  *oxycephalus* row though iNat lists *oxycephala* as accepted.
- `scripts.dedupe` rebuilt park_species. **tid collisions 13 → 0.** species 24786 → 24773.

### 🟠 #5 Placeholder / wrong common-names (genus or higher-taxon vernacular)
GBIF higher-taxon vernacular pollution put genus/phylum names on specific species:
- `Onychium japonicum` → `維管束植物門` (Tracheophyta!) + en `Tracheophytes`, np=220
- `Buddleja davidii` → `フジウツギ属`; `Zinnia elegans` → `ヒャクニチソウ属`;
  `Kalmia latifolia` → `カルミア属`
- **FIX #5** (`/tmp/fix_genus_ja.py`): pulled the authoritative species-level ja
  name from iNat (locale=ja) by each row's own tid; accepted only real katakana,
  non-rank-suffix. Applied 4 ja fixes + 1 en cleanup; old values in `name_fix_log`;
  new ja added as alias.
- **Skipped & flagged:** `C. acuminata` (id 74, ja `カリッサ属`/Carissa) — its
  `inat_taxon_id` 64128 actually resolves to a **eucalyptus** (セキザイユーカリ);
  the tid is mis-bound. Left unchanged (genus stub ≥ wrong species). See open items.
- Romaji placeholders (5: `tsuru-ume-mo-doki` …) and the 7 legitimate genus stubs
  (`モンステラ属` etc., per HANDOFF) NOT changed.

### 🟠 #7 Park-local gallery — cross-species shared GBIF photos
`park_species_photo` (derived park-local gallery) attached one GBIF occurrence
image to several co-located taxa (e.g. a smut fungus + its host plant; several
fish from one survey). **1,672** rows shared a URL across >1 species — wrong for
all but at most one, unadjudicable. Quarantined to `park_species_photo_quarantine`
(`/tmp/fix7_psp_shared.py`); table is fully regenerable via
`scripts.park_species_photo`. **Pre-existing tool behavior (GBIF sourcing), not
introduced by this audit.** Recommended permanent fix: make
`park_species_photo.py` never reuse a URL across species_ids. **Now 0 shared.**
